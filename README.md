# vtile

A tiny command-line tool that takes a large image and breaks it into tiles. I built it while experimenting with [virtual textures](https://github.com/shlomnissan/virtual-textures) and needed a quick way to generate tile sets from 8K and 16K assets.

`vtile` doesn’t try to do anything clever. It just loads an image, checks that it divides cleanly into the tile size you asked for, and writes out the tiles with a simple naming scheme. That’s it.

### Features
- Split any image into tiles
- Ensures the dimensions are divisible by the tile size
- Preserves the input format
- Optional post-processing filter selection
- Optional per-tile padding for correct texture filtering
- Optional prefix for tile naming

### Example

The repository includes a sample 8192×8192 image (example.png) you can test with. It was created by Maurus Löffel. Higher resolutions and source files are [available here](https://drive.google.com/drive/folders/1K_G_hbFyohR8-xCCAlYx8xhsd_a7Ir7G).

#### Basic usage
```bash
python3 vtile.py -i example.png --tile-w 1024 --tile-h 1024
```
This will generate a tiles directory containing multiple LODs.

Tiles are named using the format `lod_x_y` to keep filenames short and easy to scan.

### Padding and filtering

Tiles are generated without padding by default. This is fine if you only ever sample tiles with nearest-neighbor filtering.

However, linear or trilinear filtering will sample across tile boundaries. Without padding this leads to visible seams when tiles are used in a virtual texture or tile streaming system.

To solve this vtile supports per-tile padding:
```bash
python3 vtile.py -i example.png --tile-w 1024 --tile-h 1024 --padding 2
```

When padding is enabled:
- Each tile includes extra pixels on all sides
- Padding pixels are generated by duplicating edge pixels (`CLAMP_TO_EDGE`)
- The core tile remains tile_w × tile_h
- The output tile size becomes `(tile_w + 2p) × (tile_h + 2p)`

This makes tiles safe to sample with bilinear and trilinear filtering without bleeding from neighboring tiles.

Padding is applied independently per LOD and does not affect tile layout or naming.

### Why this exists

Virtual textures and tile streaming rely on breaking large images into pages. I needed a simple repeatable way to generate tile sets for experiments and tests.

`vtile` is the small boring part of the pipeline, the part that should just work so you can focus on page tables, residency, feedback passes, and everything else that’s actually interesting.
